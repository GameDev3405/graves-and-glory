## Freeze rules

2. Java changes on main during the port are bug fixes only. Each one goes in the ledger below.
3. Parked until after the port: drop board (`ui/drop-board`, dropboard media), Old Hold wiring, UI editor, ai/pathing follow-ups, and the other parked lanes in class (c).
4. Superseded branches are kept on disk and never carried into the port.
5. Work with real Java waits, or is re-applied on the ported code. Maps and prop lanes: data lands on main now; their Java is rebuilt on 1.21.1 later.
6. Old maps (rows 0 to 4) stay until after the port. Decide again after 1.21.1.

## What "data-only" means

A lane is data-only only if its commits change none of these:

- any file under `src/main/java`
- any Java under `test-tools/`
- any build file or config: `*.gradle`, `gradle.properties`, `fabric.mod.json`, mixins json, `tools/package.py`, `tools/export_modrinth.py`, `dependencies/`

Json, png, nbt, ogg, lang, bbmodel, docs are data. Spec.java is generated by preflight and counts as Java.

A lane that calls itself art, anim or props can still fail this test. The nine `props/a-*` lanes, `props/f-blocks`, `props/maps-a` and `maps/redesign` all touch Java.

## GeckoLib verdict: rename, not redesign

GeckoLib 4.8.4 to 4.9.3. Only 7 classes touch it. Source: `status/port-geckolib-493.md`.

- Five controllers: rename only. Swap `IValue` for `MathValue` (fixes all 24 type errors), plus the package renames the spike already did.
- GeoTroop: rename only.
- GeoTroopRenderer: small edit.
  - `preRender` and the Trim layer `reRender`: four colour floats become one packed ARGB int (white is `0xFFFFFFFF`).
  - `applyRotations`: override the 6-argument version (with `nativeScale`). The old 5-argument one is never called, so troops would get vanilla death tip and sleep rotations. This compiles with only a warning. Check it in game.
- Also: `AttackController` line 225 attribute modifier ids are Identifiers (vanilla change).
- Not verified: nothing was compiled or run. Check in game: a troop dying, bow draw frames, a veteran trim.

## Lane layout

1. Core lane first (Opus): `GravesAndGlory.java`, `GravesAndGloryClient.java` and the build files (Gradle, Loom, `fabric.mod.json`, mixins json). Nothing else starts on those files.
2. Then parallel lanes split by file ownership: networking, rendering and mixins, items and props, GeckoLib, harness. One owner per file.
3. Already built, not on main:
   - `port/tools` (`bb-port-tools`): pins, dependencies, server-kit, builder server. Touches no Java or build files.
   - `port/resources` (`bb-port-resources`): pack formats, singular data folders, `.stk` grass rename. Tip `e1b4b3b8`.
4. At most two Gradle builds at once, to keep RAM under 95%.
5. Workers: Sonnet for easy tasks, Opus for implementing and harder ones, Fable 5.2 only as the port session's advisor.
