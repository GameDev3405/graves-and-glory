# Command panel and troop orders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the R menu screen, the CommandMode aim flow and the HUD order cards with the approved left-edge pennant panel and five distinct orders (Attack, Charge, Follow me, Retreat, Formation), with ground outlines, strong feedback and custom groups.

**Architecture:** The server keeps owning order state (`GravesAndGlory.Battle.tactical` / `issue` / `Assignment`, `Tactics.tick`). Player Formation is issued as the existing `hold` order plus a shape, so Hold's slot, wall and arrival code keeps working; Move and Hold stay as internal order ids for bots, Siege and Muster. New behaviour lands behind small new classes (`OrderRules`, `FormationRules`, `CommandNet`, `CommandPanel`, `OrderOutlines`, `ChargeCamera`, `CustomGroups`) so parallel workers do not share files. Every tunable number is a sheet column in `sheets/design.json`, generated into `Spec.java` by `tools/preflight.py`.

**Tech Stack:** Java 17, Fabric 1.20.1 (Loader 0.16.14, API 0.92.2+1.20.1, Yarn build.10), Python 3.12 preflight, Gradle 8.8 wrapper, the isolated client harness (`test-tools/isolated-checks.gradle`).

**Spec:** `docs/superpowers/specs/2026-11-04-command-ui-design.md` (APPROVED by Kort 2026-11-04, including the Builder's calls). Read it beside this plan.

## Global Constraints

- Spec.java is generated by `python tools/preflight.py`; never hand-edit it. Commit `sheets/design.json`, `sheets/preflight.json` and the regenerated `Spec.java` together.
- Server owns order state; the client renders panel, outlines and camera. The client never decides an order's target point for Attack, Follow me or Retreat (the server reads the player).
- Every behaviour is proven by a real game test through the client harness (`gradlew runClient -PlocalIntegration -I test-tools/isolated-checks.gradle`), never by computer-use. Unit-level math may add standalone checks in `test-tools/standalone/` as well, never instead.
- Visual standard: the existing UI art rules (1 texel per pixel, House colours, gold trim). Pennants about 55% opacity. Nothing drawn in the centre third of the screen.
- Keys: Attack Z, Charge X, Follow me C, Retreat V, Formation B, panel R (`menu`), Enter confirm, Backspace cancel. All rebindable in Controls.
- Save/protocol changes are approved by the spec. Older profiles (schema 4) must load unchanged; new packet ids get a `_v1` suffix; changed packets bump their version.
- Balance is closed (Kort 2026-11-02): only the numbers this plan adds, as starting values for playtesters.
- No push, no publish. One writer per file: the File ownership table below is binding.
- Model routing per `docs/WORKFLOW.md`: **[Opus medium]** hard tasks, **[Sonnet high]** routine ones.

## Review Focus

1. **Bots and Siege still hold objectives.** Map-wide hunting must apply only to a player's Attack (`Assignment.hunt`), never to a bot's or SiegeMode's `attack` with an objective target. Test in Task 6.
2. **Panel open while walking does not leak input.** With the panel open, WASD walks, left click selects and never swings or uses an item, number keys never fire relics (`hotbarKeys[0..2]` send `relic:N` today). Test in Task 7.
3. **Commander dead or respawning.** Follow me / Retreat with the commander in `battle.respawns` must not walk troops to a stale point or to a spectator. Test in Task 6.
4. **Charge with nothing ahead or off the map edge.** Direction toward the arena edge or river clamps to dry ground inside `inArena`; troops stop and switch to Attack. Test in Task 6.
5. **Disconnect mid-aim.** Charge camera, open panel and teammate outlines all clear on disconnect (`GravesAndGloryClient.resetHud`). Test in Tasks 7 and 9.

## Shared interfaces (decided here)

- **Packet `tactical_v1` stays as it is** (`group`, `action`, `formation`, `x`, `z`, `yaw`, `target`). New meaning of `action`:
  - `attack`: x/z ignored; server stores `Assignment(order="attack", target=group centre, hunt=true)`.
  - `charge`: x/z = the aimed start point (group centre), `yaw` = direction; `target` = -1 allowed.
  - `follow`, `retreat`: x/z ignored; server uses the player.
  - `hold`: the player's Formation order: x/z = outline anchor, `yaw` = player's look yaw, `formation` = shape id.
  - `formation` (shape-only change, today's B key) stays accepted for old clients.
  - `group` may also be `custom:<n>` (Task 12); until then the server ignores it.
- **New packet `command_v1` (S2C, `CommandNet`):** a byte kind then fields.
  - `0 COOLDOWN`: `int chargeReadyInTicks`.
  - `1 OUTLINE`: `int ownerTeamSlot`, `String formation`, `double x,z`, `float yaw`, `int count`, then `count` x `(String group, int members)`; sent to the issuer's teammates only, never to enemies.
  - `2 ACK`: `String order`, `int[] unitEntityIds` (the troops that raise weapons), `double x,z` (pulse centre); sent to the issuer and teammates.
- **Server API added by Task 3** (in `OrderRules`, package-private, static):
  - `static void playerOrder(GravesAndGlory.Battle b, ServerPlayerEntity p, String group, String action, String formation, double x, double z, float yaw)` – the single entry the `tactical` handler calls.
  - `static boolean chargeReady(GravesAndGlory.Battle b, GravesAndGlory.Squad s)` and `static void markChargeUsed(GravesAndGlory.Battle b, GravesAndGlory.Squad s)` – also used by bots (Task 11).
  - `static String loadOrder(String order)` and `static String loadFormation(String formation)` – compat mapping (`move`/`hold` -> `hold`, `block` stays `block` which is now labelled Shield wall).
- **`Assignment` gains:** `boolean hunt` (player Attack), `Vec3d chargeDir` (unit vector, null unless charge), `boolean thenFollow` (Retreat switches to Follow me on arrival).
- **`FormationRules` stubs (Task 3, filled by Task 6):** `static double moveShare(GravesAndGlory.Unit u, GravesAndGlory.Assignment a)` (1.0), `static float arrowBlock(GravesAndGlory.Battle b, GravesAndGlory.Unit victim, Entity arrow)` (0), `static void shove(GravesAndGlory.Battle b, GravesAndGlory.Unit u, GravesAndGlory.Assignment a)` (no-op), `static boolean surrounded(GravesAndGlory.Battle b, GravesAndGlory.Unit u)` (false).
- **Client API added by Task 4:** `CommandSelection` (static): `List<String> selected()`, `void select(String groupId, boolean add)`, `List<Pill> pills()` with `record Pill(String id, String label, int members, boolean custom)`, `boolean panelOpen()`, `void setPanelOpen(boolean)`, `boolean trayOpen()`, `void setTrayOpen(boolean)`, `String aiming()` (`""`, `"charge"` or `"hold"`), `void order(String action, boolean keepOpen)`.
- **Harness:** `CommandUiChecks` reads `-Dgravesandglory.commandUiChecks=a,b,c` (env `GRAVES_COMMAND_UI_CHECKS`) and loads each suite reflectively as `gg.gravesandglory.cmdui.<Name>Suite` implementing `CommandUiChecks.Suite { void tick(MinecraftClient c, int tick); default void serverTick(GravesAndGlory.Battle b) {} void cleanup(MinecraftClient c); }`. Reports go to `<run>/command-ui/results.txt` as `PASS|FAIL <check> <detail>`. A suite file is owned by its task; no shared registry edit.

Run a suite: `$env:GRAVES_COMMAND_UI_CHECKS='<Name>'; .\gradlew.bat runClient -PlocalIntegration -I test-tools/isolated-checks.gradle` and expect `PASS cu-<name>-suite` with no `FAIL` lines.

### Task 6: Formation rules and charge impact [Opus medium]

**Files:** Modify `FormationRules.java`, `Combat.java` (`charge` near 55, arrow damage path). Test: `cmdui/FormationRulesSuite.java`, `test-tools/standalone/FormationRulesCheck.java`.

**Interfaces:** Implements the four stubs. Adds `static boolean firstChargeHit(GravesAndGlory.Battle b, GravesAndGlory.Unit attacker)` used by `Combat`.

Rules:
- **Shield wall (`block`):** `moveShare` = `moveMultiplier` (0.85). A shield troop in the front rank (place row 0) with shield up blocks `arrowBlock` (0.75) of arrow damage from within +-60 deg of its facing. `surrounded` = enemies sighted in 3 or more of 4 quadrants around the group centre; then `Battle.formation` lays the shield troops as a square facing out (`BattleMath.squareLayout(int n, double cell)` returning `{side, back, facingYaw}` rows) and the front-arc test uses each troop's own facing.
- **Wedge:** the point troop and the two flanking it, while walking, push enemy troops within 1.2 blocks sideways with velocity `shove` (0.6) away from the wedge axis; at most once per 10 ticks per enemy.
- **Loose:** spacing from the sheet only; no extra rule.
- **Charge impact:** the first landed melee blow of each charging troop after a run of at least 6 blocks multiplies damage by `chargeBonusMultiplier` (1.3) and knocks back by `chargeKnockback` (0.8); stacks with counters C5/C6 as a separate multiplier; never twice per troop per charge.

## Spec gaps found while planning (builder defaults used; flag to Kort)

1. **Groups:** the code has six groups (all, infantry, ranged, support, cavalry, siege); the state packet sends only three (infantry, ranged, support), so Riders have no card today. The spec names four pills. Default: pills Infantry 1, Archers 2, Riders 3, All 4, then Support and Siege (no number key) when fielded; the state packet group count is raised to five (protocol change, Task 3).
2. **Saves hold no orders.** Orders live only in battle memory; nothing on disk stores Hold, Move or Compact. The "saved Hold loads as Formation Line" call reduces to mapping ids at intake and in bots (`loadOrder`).
3. **Attack hunting vs objectives.** Bots and SiegeMode use `attack` with an objective target. Map-wide hunting is limited to a player's Attack (`hunt`), or bots would abandon objectives.
4. **Missing starting numbers:** charge bonus 1.3x, knockback 0.8, Shield wall arrow block 75% and speed 0.85, Wedge shove 0.6 are this plan's guesses.
5. **Retreat and shields:** today a retreating shield troop never raises its shield (`BattleMath.raiseShield`), so "normal shield blocking still works" needs a ruling: kept as today.
6. **Formation travel** is unspecified; it travels as Hold does (engages within 10 blocks of the anchor).
7. **Number keys vs relics:** keys 1-3 fire relics in battle today; with the panel open they pick groups instead.
