# 0.6.0 The Field Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every match a visible condition and a physical standard, so the same banner and the same map play differently, a losing match has a comeback, and the battle sounds and reads like a battle.

**Architecture:** A `conditions` sheet holds six fields (calm, rain, fog, night, blizzard, gale) and one pure `Conditions` class answers every question about them. `Combat.resolve` multiplies one condition factor after its counters, traits, auras and commander factors; `Tactics.walk` reads the movement multiplier; `Morale` the rout delta; `Abilities` the night rise bonus. The round stores its condition at `startRound`, sets the world time and weather there, restores both at teardown, and rides the condition in a new STATE layout. A `Standard` is an armour stand implementing `ArmyMob` in the `ArmySupplyBanner` pattern, at `Battle.fieldBase(team)`, with HP, an aura read by `Morale`, and Phase 4's Banner-mode pickup, carry, drop and return code for its fall. Audio, camera and camp life are client-only and read the snapshot the client already receives.

**Tech Stack:** Minecraft 1.20.1, Fabric Loader 0.16.14, Fabric API 0.92.2+1.20.1, Yarn 1.20.1+build.10, Loom 1.7.4, Java 17, Gradle 8.8 (offline); Python 3.12.2 with Pillow and numpy (`tools/ui_art`, `tools/preflight.py`, `tools/condition_gate.py`); ffmpeg `C:\ffmpeg\ffmpeg-8.1-full_build\bin\ffmpeg` (contact sheets).

**Spec:** `docs/superpowers/specs/2026-10-19-growth-design.md` sections 5, 6, 13, 15 and 16. It extends `docs/VISION-AND-ROADMAP.md`; the pillars (section 3) and the workflow (section 12) bind every task. The Houses spec binds the Tidecallers rain clause; the Phase 4 spec binds the mode frame, the teardown rules and the Banner-mode carrier; the UI spec binds the ledger and feed widths; the story spec binds every player-facing string and the 140 px feed limit.

**Base:** branch `0.6-the-field`, cut from the 0.5.0 merge of `phase-1-solo-core`, `phase-2-houses`, `phase-3-built-world`, `ui-plan` and `phase-4-modes-campaign`, each complete to its plan. The merged STATE is `state_v9`; this plan makes it `state_v10`. Phase 4's `fieldBase`, `BattleMode`, `BannerMode` carrier and `FeedLines` exist on that base; if any is missing, stop and report rather than inventing a parallel one.

## Review Focus

1. A round that ends while a standard is carried, while it is down, or while the portcullis countdown of a Siege round runs: the standard is discarded, the carrier's helmet, glow and speed are cleared, no return timer fires later, and the next round on that map starts with both standards up. (Tests: `p6-std-teardown`, Task 8.)
2. A condition on a map whose world clock and weather were not the defaults (a Survival round that set midnight, a scene that set fog, a previous blizzard): `startRound` records what it found, applies its own, and teardown restores exactly what it found. (Tests: `p6-cond-restore`, Task 2; `p4-mode-teardown-mid` still passes.)
3. The condition factor never rewrites the counter table: a shield still stops most arrows in rain, and a charge still crashes archers in gale. (Tests: `p6-cond-shot`, Task 3, asserts the composed factor, not just the condition factor.)
4. A standard is not a structure: it takes no C10 or C11 multiplier, a siege troop does not quadruple it twice, and arrows do not clear it in one volley. (Tests: `p6-std-damage`, Task 8.)
5. The state packet read order: a `state_v9` client against a `state_v10` server is refused by the version gate, and a `state_v10` pair reads every field in order with the snapshot still last. (Tests: `p6-cond-packet`, Task 2.)

## Constraints from the merged code (and the smallest change chosen)

- `Combat.resolve(b, attacker, target, base, kind, secondary)` builds `CounterMath.Hit`, multiplies counters, traits, auras and commander factors, clamps and applies. Task 3 inserts exactly one factor between the commander factor and the clamp, and one field in `HitLog`. Nothing else in the class changes.
- `HitLog` is a record with seven components and is read by `Diagnostics` and the harness. Adding an eighth component at the end keeps every constructor call compiling only where this plan edits it; the harness prints it.
- `Tactics.walk(battle, u, destination, time, speed)` is the only movement entry. Task 3 multiplies `speed` by `Conditions.move(b.condition)` inside it, so every caller (orders, follow, rout, retreat) inherits the condition.
- `Morale.tick` reads `M.routShare()` and `M.flankedRoutShare()` and compares through `BattleMath.shouldRout`. Task 3 adds `Conditions.routDelta(b.condition)` and Task 8 adds the standard's aura delta through `b.standardRoutDelta(team, centre)`. The lowest share wins, as Phase 4 rules for Siege.
- `Abilities` owns Rise Again on the Phase 2 branch. Task 3 adds `Conditions.riseBonus(b.condition)` to the roll and caps the sum at the House trait's tier III value, read from `houseTraits`.
- `Battle.startRound` builds the round; `Battle.finish` and `Campaign.returnLobby` tear it down. Phase 4's `BattleMode.teardown` restores mode pieces and the world clock. Task 2 stores the pre-round time and weather on the `Battle` before applying the condition, and restores them in the same teardown, so a phase-4 round and a condition round never fight over the clock.
- `sendState` writes a fixed sequence ending with `campaign.snapshot(p)`. Task 2 inserts the condition and two standards before the snapshot string and bumps `STATE` to `state_v10`; `CampaignClient` reads in the same place. The version gate refuses a mismatch.
- `Battle.fieldBase(team)` (Phase 4) is the standard's position: it already answers per mode and per map, so the standard follows the base and never a sheet coordinate.
- `ArmySupplyBanner` is the structure-target pattern: an armour stand implementing `ArmyMob`, tag `structure`, HP in a field, `damage` subtracting the resolved amount. `Standard` copies the pattern with tag `standard` and no counter rows.
- `BannerMode` owns the carrier: helmet, glow, speed multiplier, no attack, pickup radius, drop, return. Task 8 extracts the carrier helpers into `Carry` (visible to `Mode` and `Standard`) rather than copying them; if the Phase 4 code is one class, the task moves the helpers without changing their behaviour and re-runs `p4-banner-teardown-head`.
- `BattleHud` draws the ledger from `R.winScore()` and the state packet; the UI plan's Task 7 reserves the condition seal slot beside the clock and the standard slot beside each team's seal. Task 4 and Task 10 fill the reserved slots and add nothing new.
- `MapScreen` draws points and friendly troops; Task 10 adds one star per base when a standard is `UP` or `DOWN`.
- `FeedLines` and `FeedEvents` own every line; Phase 4 reserves the five ids this plan uses. Task 4 sends the condition line at `startRound`; Task 10 sends the four standard lines from the state changes only, never per tick.
- `Campaign` holds the lobby settings (`map`, `difficulty`, `battleMode`) and `campaign.snapshot` sends them. Task 2 adds `field` to the same object and a `field:<id>` command beside `battlemode:<id>`.
- `CampaignMaps.select` rewrites `Spec.FACTIONS` spawn and barracks per map. The standard reads `fieldBase`, never the sheet rows, so no map edit is needed.
- `sounds.json` and the six cue registrations in `GravesAndGlory` own the sounds. Task 12 adds `ambience_camp`, `ambience_battle_low`, `ambience_battle_high`, `rain_loop`, `drum_charge` and `standard_fall` as entries whose files exist in `assets/gravesandglory/sounds/`; a missing file fails `p6-audio-missing`.
- Camp NPCs and the dog carry `CampWorld.TAG` and are discarded on rebuild like every camp entity. Task 14 never adds a `gravesandglory` tag to a camp entity (the battle's `clearOldUnits` would kill it).

## Self-review

- The six fields, the standard and the immersion pass are the only scope. Sergeants, the barrow, oaths, the front, rivals, the chronicle and photo mode are explicitly later; 0.6 adds no profile field, so it cannot block 0.7's migration.
- Every new number is a sheet cell; every new string is copy-owned; every new visual is graded.
- The riskiest refactor is `Carry` (Task 8); it is proven by re-running the Phase 4 Banner checks before and after.
- The riskiest balance change is the condition factor. It is one multiplication, it is gated by Task 6's sims, and it is opt-in in Skirmish and fixed in the campaign.
- The plan's tasks are ordered so every one compiles, ships its own checks and leaves the game playable.
