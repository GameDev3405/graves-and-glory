# UI and HUD Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved Iron Ledger battle HUD, War Table camp screens and "The Hill" title screen into Graves and Glory, painted by the mockups' own painters, with live data, no hunger, glyph-backed colours and binding-aware hints.

**Architecture:** A Python exporter (`tools/build_ui_art.py`) paints every texture from committed copies of the mockup painters into `textures/gui/` with an `atlas.json`. On the client, `UiCanvas` gives every screen a pixel-exact canvas (k screen pixels per design pixel), `UiTex` draws atlas textures (fixed, 9-slice, 3-slice, sheets), `UiButton` puts clickable boxes on that canvas, and one class per place lays out the mockups' exact positions (`BattleHud`, `EventFeed`, `TitleScene`, `WarTable*`). Maths and copy live in pure classes with no Minecraft imports (`UiMath`, `HintText`, `FeedLines`) checked by a standalone `javac` run; in-game behaviour is proved by new `Phase1Checks` suites with named screenshots.

**Tech Stack:** Minecraft 1.20.1, Fabric Loader 0.16.14 (bundles MixinExtras), Fabric API 0.92.2+1.20.1, Yarn 1.20.1+build.10, Loom 1.7.4, Java 17, Gradle 8.8 (offline); Python 3.12.2 with Pillow and numpy (exporter only); ffmpeg `C:\ffmpeg\ffmpeg-8.1-full_build\bin\ffmpeg` (title ambience, screenshot comparisons); for the panorama capture only, Iris 1.7.6, Sodium 0.5.13 and `ComplementaryReimagined_r5.5.1.zip` copied from the repo's own `run/` folder.

**Spec:** `docs/superpowers/specs/2026-10-18-ui-design.md`. Pixel values come from `work/ui-concepts/v4-hud-iron-ledger.html` (02:14), `v4-ui-war-table-home.html` (02:22) and `v4-ui-war-table-recruit.html` (01:52), all v4.1 of 2026-10-18, and from `work/ui-concepts/title/`: `TITLE.md` (01:38) and the title pages and painters as rebuilt at 03:13.

## Conventions used by every task

- Positions are design pixels on the canvas. `W = UiCanvas.width()`, `H = UiCanvas.height()`, `cx = W/2`. A "box" is an element's layout rectangle; `UiTex.draw` places a texture so its box origin lands on (x, y) by subtracting the atlas offset (ox, oy).
- Mockup-comparison screenshots are taken in a 960x540 window at GUI Scale 1. Then k = 1, the canvas is 960x540 and vanilla's hotbar and hearts are at mockup size, so a screenshot is the mockup at 1x. The helper `Phase1Checks.window(c, w, h, gui)` (Task 1) sets this and waits 5 client ticks.
- Colours named in CAPS are `DarkUi` tokens from Task 1. "8 px" text is the default Minecraft font at 1x; `heading(...)`, `body(...)` and `focal(...)` are the `DarkUi` font helpers.

**Interfaces:**
- Produces (exporter): `python tools/build_ui_art.py` paints every manifest entry. `--verify` repaints into a temp dir, then exits 1 naming the first PNG whose RGBA differs, any PNG missing from or extra to `atlas.json`, or any texture name used in Java (regex `UiTex\.\w+\(\w+,\s*"([a-z0-9/-]+)"`) that the atlas lacks. `--import <dir>` refreshes the copies and is run only when a task says so. The script re-executes itself with `PYTHONHASHSEED=0` when that is unset, and refuses to run under a Python other than 3.12.
- Produces (`atlas.json`): `{"python":"3.12","textures":{"<folder>/<name>":{"w":int,"h":int,"ox":int,"oy":int,"kind":"fixed|nine|three-h|three-v|sheet","l":int,"t":int,"r":int,"b":int,"frames":int}}}`. Here `w,h` is the PNG size, `ox,oy` the box origin inside the PNG, `l,t,r,b` the slice insets, and `frames` the number of equal horizontal cells.
- Produces (pure `UiMath`): `pixelScale(int fbW,int fbH,int guiScale)->int` = `min(guiScale, max(1, floor(min(fbW/960.0, fbH/540.0))))`; `trim(String s,int maxW,java.util.function.ToIntFunction<String> width)->String` (longest prefix plus "..." that fits; unchanged if it fits); `contrast(int argbA,int argbB)->double` (WCAG 2 ratio); `brassKeyWidth(int textW,int chars)->int` = `chars==1 ? 13 : min(48, textW+9)`; `chipWidth(int textW)->int` = `max(10, textW+4)`.
- Produces (client): `UiCanvas.k()->int` = `UiMath.pixelScale(fbW, fbH, (int) window.getScaleFactor())`, the effective scale, so GUI Scale Auto (stored as 0) works; `width()->int`, `height()->int`, `begin(DrawContext g)` and `end(DrawContext g)` (push and pop a matrix scale of `k / window.getScaleFactor()`), `toCanvas(double guiCoord)->double`, `guiBox(int x,int y,int w,int h)->int[]`, `scissor(DrawContext g,int x,int y,int w,int h)` and `endScissor(DrawContext g)`. The scissor pair flushes with `g.draw()` and calls `RenderSystem.enableScissor(x*k, fbH-(y+h)*k, w*k, h*k)` / `disableScissor()` directly, because `DrawContext.enableScissor` ignores the matrix stack.
- Produces (client): `record UiTex.Entry(Identifier id,int w,int h,int ox,int oy,String kind,int l,int t,int r,int b,int frames)`; `UiTex.entry(String name)->Entry` (throws `IllegalArgumentException` naming an unknown name); `has(String)->boolean`; `draw(DrawContext g,String name,int x,int y)`; `frame(DrawContext g,String name,int frame,int x,int y)`; `nine(DrawContext g,String name,int x,int y,int w,int h)`; `three(DrawContext g,String name,int x,int y,int length)` (direction from the kind); `part(DrawContext g,String name,int x,int y,int u,int v,int w,int h)` (a sub-rectangle of the PNG, no offset); `bar(DrawContext g,String name,int x,int y,int length,boolean fromRight)` cuts a fill whose dark edge is its end column down to `length` (0 draws nothing): from the left it draws the first `length-1` columns and then the last column, from the right the first column and then the last `length-1` columns, so the edge stays at the inner end exactly as `hp_fill(n)` and `track(56,f)` paint it. Slices tile their edges and middles, never stretch. Every draw uses `DrawContext.drawTexture(Identifier,int,int,int,int,float,float,int,int,int,int)`.
