# Graves and Glory workflow

Approved by Kort on 2026-10-25 by requesting execution of optimization proposal v2. This policy supersedes conflicting model, effort, concurrency, question and retry instructions in older plans, memories, worktrees and generic plugin defaults. Preserve gameplay requirements and quality gates. Read HANDOFF.md next; do not restart historical next-actions.

## Planning and authority
- Ask scope/design questions before planning. After presenting a plan, surface newly discovered material questions before implementation. Do not re-ask settled preferences.
- During approved unattended work, decide reversible implementation details and log assumptions. Park dependent work on unresolved gameplay, art direction, saves, protocol or release decisions; continue independent approved tasks. Completion reports include evidence and remaining questions.
- Changes to dependencies, progression/campaign rules, saves or multiplayer protocol need Kort's decision unless already approved. Do not push, publish, send external messages, purchase, or merge gameplay branches under this workflow alone. Do not use Melty tools. Do not manufacture work or infer approval from elapsed time.

## Models and workers
- Sonnet is the Claude coordinator/normal implementation default, using the available account alias, not a speculative version ID. Use an available cheaper model for narrow mechanical work with clear checks. Escalate difficult diagnosis, architecture or unresolved quality problems to a stronger available model.
- The old blanket no-Opus/no-Haiku/no-Codex rules and mandatory xhigh art effort are replaced by this task-based policy. This does not make unavailable models available. Verify the execution environment's model choices; do not change the current chat's model by assumption.
- Ordinary effort first; increase for concrete difficulty or failed checks. Art still needs visual evidence and its established acceptance threshold; reasoning effort is not a quality score.
- **Kort's model rules (2026-11-07, updated 2026-11-09):**
  - Sonnet 5.5 at high effort for routine work, checks and reviews.
  - Opus 5.5 at medium effort for complicated or important work.
  - When stuck, escalate to Opus 5.5 at high effort. xhigh only when a task explicitly needs it.
  - Never any Fable model, in the main session or any subagent. The hook `tools/model_guard.py` (see SETUP.md) blocks Fable subagents.
  - Everything gets reviewed: one fresh Sonnet 5.5 high review per change.
- Sessions (Kort, 2026-11-09): one coordinator plus six leads (animation, unit textures, lore, props, workflow, UI). Leads use subagents, not further sessions. Nobody works in the `main` checkout; branches reach `main` only through `tools/land.py`. One writer per file/checkout. Each brief names outcome, checkout/base, owned files, exact references, acceptance checks, model/effort, stop condition and report path. Fresh workers for unrelated work; resume only related fixes.
- Up to two automatic correction rounds. Batch concrete defects (clipping, unreadable labels, failed controls, persistence, state). If material defects remain, mark incomplete/blocked, retain evidence and move to independent approved work. Never pass a broken result to satisfy the cap.

## Quality and testing
- Preserve required functional, migration, persistence, networking, package and visual checks. Use tools/verify.py fast|game|release; see SETUP.md. Fast never launches Minecraft. A smoke run is not six-player or visual acceptance.
- Compare the durable selected references in docs/visual-references at normal and small window sizes, plus hover/focus/selected/disabled/error states where relevant. Exercise controls and transitions interactively.
- Existing rubric thresholds remain: player-facing work normally 9, internal-only assets 8.5, and explicitly accepted exceptions remain documented. Use observable findings, not repeated numerical scores alone, to request corrections.
- Overnight game/server testing is permitted unless Kort is gaming. Never stop his game. Ceiling is five harness clients across all worktrees (Kort 2026-11-01), one per worker, at most 30 minutes each; no compilation in a checkout with a running client. The verification runner defers only when a client from its own checkout is running. Use isolated work run roots, never player saves. Headless bots do not prove six networked players.
- Spec.java is generated by tools/preflight.py; never hand-edit it. Save generated before/after hashes. Commit only named task files when committing is authorized; never commit bulk run data or credentials.

## Navigation and Graphify
- Read known file locations directly. For unfamiliar relationships, first check `python tools/graph_state.py check`, then bounded queries: `graphify query "question" --budget 1200 --graph <this-checkout>/graphify-out/graph.json`. Confirm results in source.
- Missing/stale/irrelevant/failing graph: use rg promptly; do not query-loop. A different branch's graph is not current evidence.
- After meaningful source batches/integration, run `python tools/graph_state.py refresh`. It uses Graphify 0.9.93 local AST extraction, GRAPHIFY_BACKEND=none and no-label clustering, then applies readable local names from `docs/graph-labels.json` and rebuilds the HTML viewer. Names follow reviewed symbol anchors rather than changing cluster numbers; new groups fall back to actual file/symbol names. This naming step makes no external model calls. The freshness record hashes dirty inputs and the graph. Do not run semantic docs/images indexing until a small experiment is approved. Do not upgrade Graphify automatically.
- Project-owned hook configuration is in tools/claude-hooks.json. Hooks are advisory, not a requirement to graph-query every known file. See SETUP.md for installation/testing. Never edit installed plugin caches as the durable fix.

## Sustainable execution
Select the next approved unblocked backlog item; implement/delegate; verify; save a short report; update BACKLOG.md and HANDOFF.md. Continue until approved work is complete/blocked or usage is exhausted. No daily ration/reserved quota, idle polling, unchanged retries, or speculative extra scope. Scheduling/restart infrastructure is a separate choice; do not promise automatic recovery from a usage limit.

Keep context focused on the active task. The configured 200k compaction window remains a trial, not a verified guarantee; at natural milestones save decisions, paths, checks and next actions. Do not restart mid-investigation to meet an arbitrary threshold.

Each task report: outcome; exact source/artifact identity; changed areas; checks/results; evidence locations; unresolved defects; assumptions/questions; implemented/tested/visually-inspected/accepted status separately. Keep full logs on disk. Record five comparable deliverables and one full usage cycle in EFFICIENCY.md, without converting API estimates into subscription charges or promising seven days.
