Branch `work/qa-client-rows`, base `main` a03efb0a. Tester: Sonnet worker. No dedicated server, no EULA, no desktop computer-use.

## Why run 2 stalled (cause found)
Not memory, a lock, a shared run dir or a port. The client was alive and idling: a `jstack` of the stalled client showed the render thread in `glfwWaitEventsTimeout` (normal frame loop), about 0 CPU, last log line right after the atlas stitch. `CampaignChecks` never opened a world. The other suites (`Phase1` to `Phase4`) press Continue on the first-run accessibility screen and call `startCamp` from the front menu; `CampaignChecks` did neither, so a fresh root sat on the Narrator/accessibility screen (and then the front menu) until killed. The log was silent because nothing was happening. Fix (test tool only): `CampaignChecks` now closes the onboarding screen, sets `pauseOnLostFocus=false`, starts the camp from the front menu, and stops cleanly at tick 1130. Also found: Minecraft names the dev player `Player<random>` per launch, so a relaunch was a different commander and `restart-collection` compared two default profiles. `GRAVES_ROADMAP_USER=<name>` (new, `isolated-checks.gradle`) fixes the name, and the restart fixture now saves a non-default gold (777, skipped when `evidence/keep-profile` exists) so the reopen proves the file was read. A first run of a fresh checkout can also crash once with `NoClassDefFoundError Veterans$Tally` (already in the modeling brief); an identical retry works.

## Follow-up rulings (Kort, 2026-11-02, branch `work/qa-rules`)
- I7/I9: a stopped or crashed match pays the participation gold pro-rated by the share of the round played (rounded down), no win bonus, shards, Renown, XP or record. A stop pays at once; a crash pays on the next start from a checkpoint written every 30 s, so up to 30 s of play is lost. Code: `MatchRules.partialGold`, `Campaign.voidMatch`, `checkpoint`, `payInterrupted`.
- J3: `/warp` is ops only; the code already required level 2.
- H8: a dropped player's slot is held 2 minutes (`MatchRules.HOLD_SECONDS`), then the reservation is released and the army stays with its bot as an ordinary seat. The 60 s bot takeover is unchanged.
- Iris and Sodium notices and `iris-source.zip` stay in the server kit. No change.
