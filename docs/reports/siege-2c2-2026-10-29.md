# Siege (2C.2) start — 2026-10-29

## Outcome

Siege is the second registered mode, and the first that hosts one map only (Ironhold, map 1). It registers only when
`gravesandglory.phase4Checks` is set, so a normal lobby cannot select it while it cannot be won; the Phase 4 checks set
that property and still construct it. The round saves the open
west gate, shuts its passage with a portcullis, takes all three point flags down, and writes the crash marker with the
saved box. `returnLobby`/`switchMap` restore the gate, raise the neutral flags and delete the saved file; a cached map
start rewrites the marker through `Modes.recover` and puts both back after a crash. The map-host refusal is now reachable
and live-tested: on Rivergate, `battlemode:siege` answers "Siege is not played on Rivergate Valley."

This is a first slice, not the whole of Task 5. Task 5's stages, `GateTarget`, wards and bot plans depend on Task 4's
world pieces (`ironhold/gate_intact`, `ironhold/ward`) and its `modeSites` sheet, none of which exist yet. The slice uses
the real open `ironhold/gate` piece, the `ih-gate` landmark row for its placement, and a programmatic portcullis over the
passage it will replace.

## What changed

- `sheets/design.json`: the `siege` modes row — map 1, 600 s, win target 3, no score interval, passive income only,
  timeout to the defenders, rule "Siege of Ironhold", the spec's three attack lines and three defend lines.
- `Structures`: `Saved(tag,file,origin,size)` with JSON round-trip; `placeSaving` snapshots the turned footprint with
  `StructureTemplate.saveFromWorld` (structure void ignored) to `<save>/gravesandglory/mode-saved/<tag>.nbt`, then places
  the piece; `restore` loads the snapshot, places it at the snapshot origin and deletes the file.
- `Arena.unflag`: removes a point's pole, cloth and lantern.
- `BattleMode.mark`: the default marker (no flags down, no saved files); `Battle.saves` holds the round's saved boxes.
  `startRound` now raises the neutral flags before `mode.setup`, so a mode can take them down, and ends with `mode.mark`
  so the marker carries what the mode changed.
- `SiegeMode`: saves and shuts the gate, unflags the three points, marks `flagsDown` with the saved box, restores
  everything on teardown, and writes a `siege` marker. A failed snapshot leaves the gate open and the flags up rather
  than closing a gate recovery could not open.
- `Modes`: registers `siege`; `recover` restores saved boxes on a matching map and confines deletions to `mode-saved/`.
- `Phase4Checks`: the `modes` suite normalises to map 0 (the save keeps the last map) and runs a new `p4-mode-siege`
  scenario on Ironhold: gate shut, flags down, marker with one saved box and its file; teardown; a second round recovered
  through `mapReady`.
