# War Table lobby (six seats) — 2026-10-30

Status: built and checked on `work/lobby-six` (cut from `work/war-table-rebase` @ `85f095e`). **Not merged or pushed.** Kort's visual acceptance is still pending.

## What it does (plan 3.4, 4C.3)
- The home page's Skirmish ride now reads "Open the war council" and opens CampScreen page `lobby` (`WarTableLobby.java`). This is a council sheet beside an orders note, in the troop sheet's frame, parchment and House colours.
- **Seats.** A room opens three a side (`social:lobby`). The host can widen it to 4v4 (eight commanders at most) or shrink it. Each side shows four seats: commanders, then BOT seats (fill on) or Open seats (fill off), then Closed. Pressing an open or bot seat on the other side moves you there.
- **Picks.** Each commander picks a House chip and a class tile on the sheet. A pick takes back that player's ready. Pads still work.
- **Host only.** Mode, map (< >), seats a side and bot fill can be changed only by the host. Everyone else sees them locked, with "Set by <host>".
- **Countdown.** When every commander is ready, the server runs 10 s (`SocialHub.countdown`, 200 ticks). Any of these stops it: a stand-down, a settings change, a pick, a leave, or a busy battlefield. At zero it runs the existing `social:start`.
- **No save or protocol change.** Rooms are transient. The new fields (mode, countdown, waiting, house/class/host/me) ride the existing social snapshot JSON. There is no new packet. createRoom's default size (2) is unchanged, so the network suite stays valid.

## Follow-up, 2026-10-31 (Kort's rulings)
Commits `3e914a4`..`49cbc55` on `work/lobby-six`. Not merged or pushed.
- **The House pick fields only that House.** `Campaign.banner` gives a room member `RosterMath.houseBanner`: units of other Houses (and their markers) become empty slots for the match. The saved banner is untouched and the pick stays transient room state, so there is no save or protocol change. The default pick is the banner's main House (`rollHouse`). The heading shows the count, e.g. "Gilded Order, 19 troops".
- **Fallback when the banner has none of the picked House: Ready is refused.** The server refuses Ready and answers the House pick with "Your banner holds no <House> troops. Pick another House, or add <House> troops on the Banner page." The plate goes dull and the sheet repeats the reason. The start also names the commander, and a Banner edit that empties the House un-readies him. There is no fallback to starter or other-House troops: that would hand out free troops or field the wrong House.
- **Chips.** Each chip shows the House's whole first word (Gilded, Graveborn, Wildmoot, Ironclad, Tidecallers). `UiMath.chipRow` sizes them so the row fits 360 px: every seal if it fits, else only the picked chip's seal, else none. Names are never cut. The full "Gilded Order" stays in the heading.
- **Scale.** `UiMath.pageScale` draws the lobby and the troop sheet at k=3 at 2560x1440 (compact layout, 853x480 canvas). k stays at 2 at 1080p, 4 at 4K and 1 in small windows, and never exceeds the GUI Scale. The other War Table pages keep pixelScale.
- **Pass host.** Only the host sees it; it sits beside a narrower Leave and is dull when no other commander is online. Pressing it lights the other commanders' seats with "Make host", and a seat press sends the existing `social:host:<name>`.
- Domination is still the only mode. The note keeps room for a second mode chip (Siege). `mode/frame` and `work/siege-dev-hook` are not merged.
- `tools/verify.py` game guard: falls back to Windows PowerShell when pwsh is missing (ported from main). The guard still runs.
