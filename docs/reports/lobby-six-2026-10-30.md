# War Table lobby (six seats) — 2026-10-30

Status: built and checked on `work/lobby-six` (cut from `work/war-table-rebase` @ `85f095e`). **Not merged or pushed.** Kort's visual acceptance is still pending.

## What it does (plan 3.4, 4C.3)
- The home page's Skirmish ride now reads "Open the war council" and opens CampScreen page `lobby` (`WarTableLobby.java`). This is a council sheet beside an orders note, in the troop sheet's frame, parchment and House colours.
- **Seats.** A room opens three a side (`social:lobby`). The host can widen it to 4v4 (eight commanders at most) or shrink it. Each side shows four seats: commanders, then BOT seats (fill on) or Open seats (fill off), then Closed. Pressing an open or bot seat on the other side moves you there.
- **Picks.** Each commander picks a House chip and a class tile on the sheet. A pick takes back that player's ready. Pads still work.
- **Host only.** Mode, map (< >), seats a side and bot fill can be changed only by the host. Everyone else sees them locked, with "Set by <host>".
- **Countdown.** When every commander is ready, the server runs 10 s (`SocialHub.countdown`, 200 ticks). Any of these stops it: a stand-down, a settings change, a pick, a leave, or a busy battlefield. At zero it runs the existing `social:start`.
- **No save or protocol change.** Rooms are transient. The new fields (mode, countdown, waiting, house/class/host/me) ride the existing social snapshot JSON. There is no new packet. createRoom's default size (2) is unchanged, so the network suite stays valid.
